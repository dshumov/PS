# Телефонный справочник из Active Directory

`phonebook.ps1` собирает данные сотрудников из Active Directory и генерирует **единый HTML-файл — телефонный справочник** с фотографиями, поиском по фамилии и фильтром по отделу. Готовый файл можно положить в общую папку: он открывается в любом браузере и не требует сервера или интернета.

---

## Что делает скрипт

1. Читает учётные записи пользователей из указанного OU Active Directory.
2. Берёт ФИО, должность, отдел, организацию, телефоны, почту, руководителя, заметки и фотографию.
3. Преобразует фотографии в base64 и встраивает их прямо в HTML.
4. Формирует страницу с фильтрами по фамилии и отделу (работают на JavaScript в браузере).
5. Сохраняет HTML-файл в общую папку и настраивает на него NTFS-права.
6. Открывает готовый справочник в браузере.

---

| Поле в карточке | Атрибут AD | Примечание |

| Должность | `title` | |
| Отдел | `department` | По нему строится фильтр |
| Организация | `company` | |
| Email | `mail` | Ссылка `mailto:` |
| Рабочий телефон | `telephoneNumber` | |
| Мобильный | `mobile` | |
| «День рождения» | `employeeID` | В скрипте это поле подписано как «День рождения» — это внутреннее соглашение. Если у вас `employeeID` используется иначе, измените подпись |

## Требования

- Windows с Windows PowerShell 5.1 или PowerShell 7+.
- Модуль `ActiveDirectory` (RSAT) и доступ к контроллеру домена.
- Права на чтение атрибутов пользователей в указанном OU.
- Права на запись в целевую папку.
- Права на изменение ACL итогового файла (для шага с `icacls`), обычно — администратор файлового ресурса.

## Настройка

Все настройки находятся в начале скрипта, в блоке «НАСТРОЙКИ».

| Переменная | Что указать | Пример |
|---|---|---|
| `$CompanyName` | Название организации для заголовка страницы | `'Моя компания'` |
| `$OutputPath` | Куда сохранять HTML-файл (UNC-путь к общей папке) | `'\\fileserver\share\phonebook.html'` |
| `$SearchBase` | DN подразделения, из которого берутся сотрудники | `'OU=Users,OU=Company,DC=example,DC=local'` |
| `$ReadAccessGroup` | Кому разрешено читать справочник | `'BUILTIN\Users'` или `'CONTOSO\Domain Users'` |
| `$DomainNetBIOS` | Короткое (NetBIOS) имя домена для `icacls` | `'CONTOSO'` |
| `$FullAccessGroup` | Группа администраторов, которой нужен полный доступ к файлу | `'FileShare Admins'` |

Пример:

```powershell
$CompanyName    = 'Моя компания'
$OutputPath     = '\\fileserver\share\phonebook.html'
$SearchBase     = 'OU=Users,OU=Company,DC=example,DC=local'
$ReadAccessGroup = 'CONTOSO\Domain Users'
$DomainNetBIOS  = 'CONTOSO'
$FullAccessGroup = 'FileShare Admins'
```

### Где взять DN подразделения (OU)

Оснастка «Пользователи и компьютеры Active Directory» → включить «Вид → Дополнительные компоненты» → свойства OU → вкладка «Редактор атрибутов» → `distinguishedName`.

## Запуск

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\phonebook.ps1
```

Скрипт выведет шаги в консоль, сохранит файл и попробует открыть его в браузере.

---

## Права доступа к файлу

После сохранения скрипт выполняет:

1. `icacls <файл> /reset` — сбрасывает явные разрешения и возвращает наследование от папки.
2. `icacls <файл> /grant:r "<ReadAccessGroup>:(R)"` — чтение для пользователей.
3. `icacls <файл> /grant:r "<Домен>\<FullAccessGroup>:(F)" /inheritance:r` — полный доступ для группы администраторов, наследование отключается.

Группа полного доступа ищется по имени `$FullAccessGroup`, затем по типовым вариантам (`Full Access to Resources`, `FullAccess`, `Resource Admins`, `File Share Admins`). Если группа не найдена, полный доступ выдаётся `BUILTIN\Administrators`, а чтение — `$ReadAccessGroup`.

> `/reset` удаляет **все** явно заданные на файле разрешения. Если на файле были особые права, которые нужно сохранить, скорректируйте этот шаг.

## Автоматическое обновление

Справочник удобно обновлять по расписанию — например, каждое утро. Пример регистрации задачи в Планировщике:

```powershell
$action = New-ScheduledTaskAction -Execute 'powershell.exe' `
    -Argument '-NoProfile -ExecutionPolicy Bypass -File "C:\Scripts\phonebook.ps1"'
$trigger = New-ScheduledTaskTrigger -Daily -At '06:00'

Register-ScheduledTask -TaskName 'AD Phonebook' `
    -Action $action -Trigger $trigger -RunLevel Highest
```

Задача должна выполняться под учётной записью, у которой есть доступ к AD и к общей папке (например, сервисной учётной записью).

## Ограничения и особенности

- **Персональные данные.** Справочник содержит ФИО, телефоны, почту и фотографии сотрудников. Публикуйте его только во внутренней сети и только с согласия сотрудников и в соответствии с политикой компании.
- **HTML-экранирование.** Значения атрибутов вставляются в HTML как есть. Если в AD-поле встретятся символы `<`, `>` или `&`, разметка может исказиться. Для аккуратного решения добавьте `[System.Net.WebUtility]::HtmlEncode()` при формировании карточки.
- **Размер файла.** Фотографии кодируются в base64 и увеличивают HTML примерно на треть от исходного размера фото. Для сотен сотрудников файл может весить несколько мегабайт.
- **Отключённые учётные записи.** Скрипт берёт всех пользователей из OU (`-Filter *`), включая отключённых. При необходимости добавьте фильтр `Enabled -eq $true`.
- **Фотографии.** В AD должен быть заполнен `thumbnailPhoto` (или `jpegPhoto`) — иначе будет заглушка.
- **Кодировка.** Файл сохраняется в UTF-8, в HTML указан `charset=UTF-8`, поэтому кириллица отображается корректно.

---

## Безопасность

- Блок цифровой подписи удалён из опубликованной версии: он содержал данные внутреннего УЦ и имя владельца сертификата. Подпишите скрипт своим сертификатом перед распространением.
- Скрипт не передаёт данные наружу: вся обработка идёт локально, готовый файл — обычный HTML.
- Ограничьте доступ к папке с готовым справочником средствами NTFS и не публикуйте файл в интернете.
