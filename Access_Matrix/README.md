# Матрица доступа к файловым ресурсам

Скрипт `FileAccessAudit.ps1` строит отчёт о том, **кто и какие права имеет на папки файлового ресурса**. Он читает NTFS-права (ACL), сопоставляет учётные записи с пользователями и группами Active Directory, разворачивает членство в группах и формирует удобные отчёты: CSV и интерактивный HTML.

Скрипт ничего не меняет: он только читает ACL и данные AD.

---

## Что делает скрипт

1. Загружает пользователей и группы из указанных подразделений (OU) Active Directory.
2. Рекурсивно обходит каталог файлового ресурса (по умолчанию — 3 уровня вложенности), включая сам корневой каталог, и пропускает исключённые пути.
3. Для каждой папки читает ACL: кому, какие права и каким способом (напрямую или по наследству) они выданы.
4. Для каждого пользователя рекурсивно разворачивает членство в группах — в отчёт попадают и права, полученные через группы, включая вложенные.
5. Сохраняет два CSV-отчёта и один интерактивный HTML-отчёт.
6. Генерирует вспомогательный скрипт `SearchUserAccess.ps1` для быстрого поиска прав конкретного пользователя.

## Требования

- Windows с Windows PowerShell 5.1 или PowerShell 7+.
- Модуль `ActiveDirectory` (входит в RSAT): `Get-ADUser`, `Get-ADGroup`.
- Домен Active Directory и доступ к контроллеру домена под учётной записью, у которой есть право читать данные AD.
- Права на чтение ACL сканируемых папок (чтение списка управления доступом). При запуске от обычного пользователя часть папок может быть недоступна — такие папки пропускаются с предупреждением.
- Права на запись в каталог отчётов.

Проверить модуль можно командой:

```powershell
Get-Module -ListAvailable ActiveDirectory
```

## Настройка

Все настройки собраны в одном блоке в начале `FileAccessAudit.ps1` — «НАСТРОЙКИ». Ниже перечислено, что нужно заменить.

| Переменная | Что указать | Пример |
|---|---|---|
| `$scanPath` | Корень файлового ресурса (локальный или UNC-путь) | `'\\fileserver\share'` или `'D:\FileShare'` |
| `$outputDir` | Каталог для готовых отчётов, создаётся автоматически | `'D:\Reports\AccessMatrix\log'` |
| `$scriptDir` | Куда сохранить сгенерированный `SearchUserAccess.ps1`; по умолчанию — папка скрипта (`$PSScriptRoot`) | `$PSScriptRoot` |
| `$usersOU` | DN подразделения с учётными записями пользователей | `'OU=Users,OU=Company,DC=example,DC=local'` |
| `$groupsOU` | DN подразделения с группами доступа к файловому серверу | `'OU=FileServers,OU=Resources,OU=Company,DC=example,DC=local'` |
| `$excludePaths` | Массив путей-исключений (папка исключается вместе с содержимым) | `@('D:\FileShare\Distributives')` |

Пример заполненного блока:

```powershell
$scriptDir  = $PSScriptRoot
$outputDir  = Join-Path $scriptDir 'log'
$scanPath   = '\\fileserver\share'

$usersOU  = 'OU=Users,OU=Company,DC=example,DC=local'
$groupsOU = 'OU=FileServers,OU=Resources,OU=Company,DC=example,DC=local'

$excludePaths = @(
    '\\fileserver\share\Distributives'
    '\\fileserver\share\Drivers'
)
```

### Где взять DN подразделения (OU)

1. Откройте оснастку **«Пользователи и компьютеры Active Directory»**.
2. Включите меню **«Вид» → «Дополнительные компоненты»**.
3. Откройте свойства нужного OU (или пользователя/группы).
4. Вкладка **«Редактор атрибутов»** → атрибут `distinguishedName`.

DN всегда начинается с `OU=` или `CN=` и заканчивается компонентами домена: `DC=example,DC=local`.

> Если пользователи и группы лежат в одном OU — укажите один и тот же DN в `$usersOU` и `$groupsOU`.

### Глубина сканирования

Глубина ограничена тремя уровнями вложенности — это задано в вызове:

```powershell
$allFolders = Get-FoldersRecursive -Path $scanPath -MaxDepth 3
```

Увеличьте `-MaxDepth`, если нужен более глубокий обход (это заметно увеличит время работы). Корневой каталог добавляется в отчёт отдельно — права, заданные на самом ресурсе, тоже попадают в матрицу.

## Запуск

```powershell
# Если политика выполнения запрещает скрипты — разрешить для текущего процесса
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

# Запуск аудита
.\FileAccessAudit.ps1
```

Скрипт выводит прогресс в консоль, а по завершении — краткую статистику и пути к готовым файлам.

## Результаты

Все файлы сохраняются в `$outputDir` (по умолчанию `.\log` рядом со скриптом). К имени файла добавляется дата и время запуска.

| Файл | Содержимое |
|---|---|
| `AccessMatrix_<дата>.csv` | Основная матрица: `Путь; Пользователь; ПолноеИмя; ИсточникДоступа; Группа; Права; ТипДоступа; Наследование` |
| `GroupMembership_<дата>.csv` | Плоский список членства: `Пользователь; ПолноеИмя; Группа; ОтображаемоеИмяГруппы` |
| `AccessMatrix_<дата>.html` | Интерактивный отчёт с фильтрами и экспортом |
| `UserAccess_<пользователь>_<дата>.csv` | Результат работы `SearchUserAccess.ps1` |

Значения колонок:

- **ИсточникДоступа** — `Прямой доступ` (пользователь явно указан в ACL) или `Через группу`.
- **ТипДоступа** — `Разрешить` или `Запретить`.
- **Наследование** — `Наследуемый` (право пришло от родительской папки) или `Прямой` (задано на самой папке).
- **Права** — переведены на русский: «Полный доступ», «Изменение», «Чтение и выполнение» и т. д.

CSV разделён точкой с запятой (`;`), чтобы корректно открываться в русской локали Excel, и сохранён в UTF-8.

### HTML-отчёт

Отчёт открывается в любом браузере и не требует интернета. Возможности:

- фильтры по пути, пользователю, полному имени, источнику доступа, группе, правам и наследованию;
- кнопки «Только прямые доступы» и «Только доступы через группы»;
- экспорт **отфильтрованных** строк в CSV;
- подсветка: зелёные строки — прямой доступ, красные — доступ через группу.

## Поиск прав пользователя

```powershell
# По логину
.\SearchUserAccess.ps1 -UserName ivanov

# По части ФИО
.\SearchUserAccess.ps1 -UserName "Иванов"

# По конкретному отчёту (по умолчанию берётся самый свежий AccessMatrix_*.csv)
.\SearchUserAccess.ps1 -UserName ivanov -ReportPath .\log\AccessMatrix_20260101_120000.csv
```

Результат выводится в консоль и сохраняется в CSV рядом с исходным отчётом.

> `SearchUserAccess.ps1` перезаписывается при каждом запуске `FileAccessAudit.ps1`. Если вы доработали его вручную, изменения нужно перенести в шаблон внутри основного скрипта (этап 6).

## Ограничения и особенности

- **Обходятся только папки.** Файлы наследуют права папки; если у отдельного файла есть исключение из правил, оно в отчёт не попадёт.
- **Сопоставление групп идёт по имени (CN).** Из `MemberOf` извлекается `CN`, а ACL содержит `sAMAccountName`. Обычно они совпадают. Если в вашем домене имя группы (CN) отличается от её логина, часть доступов через группы может не развернуться — проверьте на нескольких пользователях.
- **Встроенные учётные записи** (`SYSTEM`, `Administrators`, `CREATOR OWNER`, `Authenticated Users` и т. п.) намеренно исключены из матрицы.
- **Время работы** растёт линейно от числа папок и пользователей; на больших ресурсах запускайте аудит в нерабочее время.
- **Отчёты содержат персональные данные** (ФИО, логины) и сведения о структуре файлового сервера. Не публикуйте их и храните в защищённом каталоге.

## Безопасность

- Скрипт работает в режиме «только чтение» и не изменяет ACL.
- Блок цифровой подписи удалён из опубликованной версии: он содержал данные внутреннего удостоверяющего центра. Перед распространением подпишите скрипт своим сертификатом — для этого можно использовать `PowerShell-Script-Signer.ps1` из этого же репозитория.
- Запускайте скрипт под учётной записью с минимально необходимыми правами (чтение ACL и чтение AD).
