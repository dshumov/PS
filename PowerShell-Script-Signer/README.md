# Подписание PowerShell-скриптов (GUI)

`PowerShell-Script-Signer.ps1` — небольшая графическая утилита для **подписания PowerShell-скриптов сертификатом Authenticode** и проверки подписи. Не требует установки: это один `.ps1`-файл на WinForms.

---

## Зачем это нужно

Неподписанный скрипт при запуске может блокироваться политикой выполнения (`AllSigned`, `RemoteSigned`), а при скачивании из интернета — помечаться как небезопасный. Цифровая подпись:

- подтверждает автора скрипта;
- гарантирует, что файл не изменялся после подписания (любое изменение ломает подпись);
- позволяет использовать политику `AllSigned` и централизованно доверять только вашим скриптам.

---

## Возможности

- Показывает **только пригодные** сертификаты: с закрытым ключом, действующим сроком и назначением «Подписание кода».
- Ищет сертификаты в хранилищах `CurrentUser\My` и `LocalMachine\My`.
- Подписывает выбранный `.ps1` алгоритмом **SHA-256**.
- Сразу после подписания проверяет файл заново — уже с диска.
- Показывает статус подписи и ведёт журнал операций.
- Отдельная кнопка «Проверить подпись» для любого файла.

Подписание выполняется стандартным командлетом `Set-AuthenticodeSignature`, проверка — `Get-AuthenticodeSignature`, поэтому результат совместим с обычными средствами Windows.

---

## Требования

- Windows (Windows PowerShell 5.1 или PowerShell 7+).
- .NET Framework с `System.Windows.Forms` и `System.Drawing` (есть в Windows по умолчанию).
- Сертификат подписи кода:
  - с закрытым ключом (иначе подписать невозможно);
  - с действующим сроком;
  - с расширением **Enhanced Key Usage → Code Signing** (OID `1.3.6.1.5.5.7.3.3`). Сертификат без EKU тоже считается пригодным.

---

## Запуск

```powershell
# Если политика выполнения запрещает скрипты
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

.\PowerShell-Script-Signer.ps1
```

Откроется окно с четырьмя блоками: сертификат, скрипт, подписание/проверка, журнал.

---

## Как пользоваться

1. **1. Сертификат → «Выбрать...»**
   В таблице отображаются владелец, издатель, хранилище, срок действия и отпечаток. Выберите строку и нажмите «Выбрать» (или дважды щёлкните по строке).
2. **2. PowerShell-скрипт → «Выбрать...»**
   Укажите `.ps1`-файл. Сразу после выбора утилита покажет текущий статус подписи файла.
3. **3. «Подписать скрипт»**
   В конец файла добавляется блок подписи, после чего выполняется повторная проверка. При успехе появится сообщение «Скрипт успешно подписан».
4. **4. «Проверить подпись»**
   Повторная проверка выбранного файла без изменения.

Кнопка «Подписать скрипт» активна только когда выбран и сертификат, и существующий файл.

## Где взять сертификат

| Вариант | Когда подходит |
|---|---|
| Сертификат публичного удостоверяющего центра (Code Signing) | Скрипты распространяются за пределы организации |
| Сертификат внутреннего УЦ (AD CS, шаблон Code Signing) | Скрипты используются внутри домена |
| Самоподписанный сертификат | Тесты и внутренние нужды |

Самоподписанный сертификат для теста:

```powershell
$cert = New-SelfSignedCertificate `
    -Type CodeSigningCert `
    -Subject "CN=My Scripts" `
    -CertStoreLocation Cert:\CurrentUser\My

$cert.Thumbprint
```

Чтобы подпись считалась доверенной на других компьютерах, сертификат (или корневой сертификат вашего УЦ) нужно установить в хранилище **«Доверенные корневые центры сертификации»**. Например, экспортировать и импортировать:

```powershell
# Экспорт (без закрытого ключа)
Export-Certificate -Cert Cert:\CurrentUser\My\<отпечаток> -FilePath .\MyScripts.cer

# Импорт в доверенные корневые (нужны права администратора)
Import-Certificate -FilePath .\MyScripts.cer -CertStoreLocation Cert:\LocalMachine\Root
```

## Статусы подписи

| Статус | Значение |
|---|---|
| `Valid` | Подпись действительна, файл не изменялся, сертификат доверенный. |
| `NotSigned` | Подписи нет. |
| `HashMismatch` | Подпись есть, но файл изменён после подписания — подпись недействительна. |
| `NotTrusted` | Подпись корректна, но цепочка сертификата не является доверенной на этом компьютере. |
| `NotSupportedFileFormat` | Формат файла не поддерживает Authenticode-подпись. |
| `Incompatible` | Подпись несовместима с текущей системой или версией PowerShell. |

---

## Важные замечания

- **Любое изменение файла после подписания аннулирует подпись.** Поэтому сначала вносите правки, потом подписывайте. В частности, скрипты из этого репозитория опубликованы без старых блоков подписи — подпишите их своим сертификатом.
- Подпись не шифрует содержимое скрипта: любой может его прочитать. Она подтверждает авторство и целостность.
- Закрытый ключ — секрет. Храните его на токене/в защищённом профиле и не передавайте вместе со скриптом.
- Чтение хранилища `LocalMachine\My` может быть ограничено политикой; в этом случае утилита просто не покажет сертификаты из него.
- Для подписи через `LocalMachine\My` обычно нужны права администратора.

---

## Возможные проблемы

| Симптом | Причина и решение |
|---|---|
| «Сертификаты не найдены» | Нет сертификата с закрытым ключом и действующим сроком. Проверьте хранилища `certmgr.msc` → «Личное». |
| Кнопка «Подписать скрипт» неактивна | Не выбран сертификат или файл. |
| После подписания статус `NotTrusted` | Сертификат не установлен в доверенные на этом компьютере. |
| `HashMismatch` | Файл изменили после подписания — подпишите заново. |
| Скрипт не запускается из-за политики | `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` или настройте политику домена. |
