# FS-AccessManager — управление доступом к папкам файлового сервера

> **Данный скрипт создан для гранулированного доступа к файловым ресурсам.**

**FS-AccessManager.ps1** — графическая утилита (PowerShell + WinForms) для администраторов Active Directory. Она позволяет выбрать или создать папку на файловом сервере, при необходимости создать для неё подразделение (OU) и три группы безопасности AD, назначить этим группам NTFS-права на папку и управлять составом групп — всё из одного окна, без ручной работы в ADUC и проводнике.

## Возможности

- Выбор существующей папки на файловом сервере (навигация по подпапкам) или создание новой.
- Автоматическая проверка наличия групп AD для выбранной папки:
  - **FS_<имя папки>_RO** — «Группа доступа к <имя папки> (Только чтение)»;
  - **FS_<имя папки>_RW** — «Группа доступа к <имя папки> (Чтение и Запись)»;
  - **FS_<имя папки>_FA** — «Группа доступа к <имя папки> (Полный доступ)».
- Создание отсутствующих групп типа **Security / Domain Local** в выбранной OU.
- При необходимости — создание **OU с именем папки** внутри выбранной OU и размещение групп в ней.
- Назначение группам NTFS-прав на папку с наследованием на подпапки и файлы.
- Добавление пользователей в группы (поиск по ФИО, логину, e-mail), просмотр и удаление участников.
- Выбор контроллера домена, файлового сервера и OU из списков, которые опрашиваются у домена.
- Журнал всех действий с сохранением в файл; сохранение параметров подключения между запусками.

## Как это работает

### Группы Active Directory

Для каждой папки используется три группы. Имена и описания формируются автоматически:

| Группа | Описание в AD | Права NTFS |
|---|---|---|
| FS_<папка>_RO | Группа доступа к <папка> (Только чтение) | ReadAndExecute (чтение и выполнение) |
| FS_<папка>_RW | Группа доступа к <папка> (Чтение и Запись) | Modify (изменение) |
| FS_<папка>_FA | Группа доступа к <папка> (Полный доступ) | FullControl (полный доступ) |

Тип групп: **Security**, область действия: **Domain Local**. Такие группы можно назначать на ресурсы в пределах своего домена; на серверах других доменов они напрямую не работают (при необходимости добавьте их вложенно в глобальную или универсальную группу).

Если группа уже существует (в любой OU домена), она не пересоздаётся и используется повторно.

### Подразделение (OU)

- Группы создаются в OU, выбранной в поле «Подразделение (OU)».
- Если включена галочка **«Создавать OU с именем папки»** (по умолчанию включена), внутри выбранной OU создаётся (или берётся существующая) OU с именем папки, и группы создаются уже в ней. Пример: выбрана **OU=FileShares,DC=example,DC=local**, папка **Sales** — группы появятся в **OU=Sales,OU=FileShares,DC=example,DC=local**.
- Если группы уже существуют, новая OU не создаётся.

### Права на папку

- На папку добавляются три явных разрешения (Allow) с областью «Эта папка, подпапки и файлы».
- Повторный запуск безопасен: старые явные ACE этих трёх групп заменяются актуальными, остальные права не затрагиваются.
- Опционально можно отключить наследование разрешений у папки — текущие унаследованные права при этом копируются как явные (галочка в блоке «Группы AD и права NTFS»). По умолчанию наследование не трогается.

## Требования

- Windows 10/11 или Windows Server 2016+.
- Windows PowerShell 5.1 или PowerShell 7.x (для 7.x запускать с ключом -STA).
- Модуль **ActiveDirectory** (RSAT):
  - Windows Server: **Install-WindowsFeature RSAT-AD-PowerShell**;
  - Windows 10/11: **Add-WindowsCapability -Online -Name Rsat.ActiveDirectory.DS-LDS.Tools~~~~0.0.1.0**.
- Права на создание групп (и OU, если включено) в выбранном подразделении.
- Права на изменение NTFS-разрешений папки на файловом сервере (владелец, администратор сервера или право «Изменение разрешений»).
- Сетевой доступ к корневой папке по SMB под текущей учётной записью (файловые операции всегда выполняются от текущей УЗ).
- Политика выполнения, допускающая запуск скрипта (см. ниже).

## Подготовка к работе

1. Скопируйте папку FS-AccessManager на рабочее место (например, D:\Tools\FS-AccessManager).
2. Разблокируйте скрипт, если он был получен из сети или архива:

       Unblock-File .\FS-AccessManager.ps1

3. Проверьте наличие модуля AD:

       Get-Module -ListAvailable ActiveDirectory

4. Если модуля нет — установите RSAT командами из раздела «Требования» (нужны права администратора).
5. Убедитесь, что у вашей учётной записи есть права на создание групп в OU и на изменение прав папки на сервере.
6. Проверьте, что корневая папка открывается в проводнике по пути вида \\файловый-сервер\шара\...

## Запуск

Из консоли PowerShell (рекомендуется):

    powershell.exe -STA -ExecutionPolicy Bypass -File .\FS-AccessManager.ps1

Или, если политика выполнения уже позволяет:

    .\FS-AccessManager.ps1

Для PowerShell 7:

    pwsh -STA -File .\FS-AccessManager.ps1

С параметрами (необязательно):

    .\FS-AccessManager.ps1 -DomainController dc01.example.local -FileServer fileserver -RootPath \\fileserver\Shared -TargetOU "OU=FileShares,DC=example,DC=local"

| Параметр | Описание |
|---|---|
| -DomainController | Контроллер домена (имя или IP). Если не задан — выбирается в окне |
| -FileServer | Имя или IP файлового сервера |
| -RootPath | Корневая папка на файловом сервере (UNC или локальный путь) |
| -TargetOU | DN подразделения, в котором создаются группы |

Примечания:

- При запуске из уже открытой консоли консоль будет занята, пока открыто окно программы.
- Если PowerShell 7 запущен без -STA, копирование в буфер обмена может не работать — скрипт предупредит об этом в журнале.

## Пошаговая инструкция

### Шаг 1. Подключение

1. **Контроллер домена** — нажмите «Обновить» и выберите DC из списка (показываются имя и IP). Можно ввести вручную.
2. **Файловый сервер** — введите имя или IP либо нажмите «Из домена...» и выберите сервер из списка компьютеров домена.
3. **Корневая папка** — нажмите «Обзор...», перейдите на \\сервер, выберите шару, затем папку; либо введите путь вручную и нажмите Enter. Список папок слева заполнится подпапками корня.
4. **Подразделение (OU)** — нажмите «Выбрать...» и укажите OU в дереве (можно выбрать корень домена). Дерево можно фильтровать по имени.
5. При необходимости отметьте **«Другая УЗ для AD»** и введите учётные данные. Если неявная аутентификация не работает, скрипт сам предложит ввести их при старте.
6. Проверьте галочку **«Создавать OU с именем папки»** (по умолчанию включена).

Если при старте появилось окно ввода учётных данных — это нормально для сред, где текущий процесс не может использовать учётные данные пользователя для запросов к AD. Введите доменную учётную запись с правами на AD.

### Шаг 2. Выбор или создание папки

- Слева показаны подпапки текущего пути. Двойной клик — войти в папку, «Вверх» — подняться (не выше корня).
- Чтобы создать папку: «Создать папку...», введите имя. Проверяются недопустимые символы, длина и занятость имени. После создания папки сразу создаются OU (если включено), группы и назначаются права.
- Выбор папки в списке сразу показывает её группы и участников.

### Шаг 3. Создание групп и назначение прав

1. Выберите папку в списке слева.
2. Нажмите **«Создать группы и назначить права»**.
3. Скрипт:
   - проверит, какие из трёх групп уже есть в AD;
   - при необходимости создаст OU с именем папки (если включена галочка);
   - создаст отсутствующие группы с описаниями;
   - назначит на папку права RO/RW/FA с наследованием;
   - обновит статусы и список участников.
4. В таблице «Группы AD и права NTFS» видно: имя группы, статус в AD (есть/нет, scope и category), права NTFS и наличие ACE на папке. Серый цвет — группы нет, оранжевый — группа есть, но права не назначены.
5. Кнопка «Обновить статус» перечитывает состояние AD и ACL.

Если папка уже была обработана ранее, повторное нажатие безопасно: существующие группы используются, ACE обновляются.

### Шаг 4. Добавление пользователей

1. Выберите папку и нажмите **«Добавить пользователей...»**.
2. Введите минимум 2 символа (ФИО, логин или e-mail) и нажмите «Найти».
3. Выделите одного или нескольких пользователей (Ctrl/Shift), отметьте группы (RO/RW/FA) и нажмите «Добавить».
4. Если пользователь не находится поиском, введите его логины вручную через точку с запятой в поле внизу.
5. Ниже, в блоке «Пользователи в группах», отображаются все участники трёх групп. Кнопка «Удалить выбранных» убирает их из групп (с подтверждением).

### Шаг 5. Проверка результата

- В ADUC (dsa.msc): выбранная OU — должна появиться OU с именем папки, в ней три группы с описаниями.
- Состав групп: вкладка «Члены» или командой:

      Get-ADGroupMember FS_Sales_RW

- Права на папке: проводник — Свойства — Безопасность — Дополнительно; либо:

      icacls "\\fileserver\Shared\Sales"

В ACL должны быть три явные записи для групп FS_Sales_RO, FS_Sales_RW, FS_Sales_FA.

## Типовые сценарии

**Новая папка отдела.** Укажите корень и OU — «Создать папку...» — введите имя. Скрипт создаст папку, OU (если включено), три группы и назначит права. Останется добавить сотрудников.

**Существующая папка без групп.** Выберите папку — «Создать группы и назначить права». Группы появятся в OU (или в OU с именем папки), права будут назначены.

**Группы уже созданы вручную.** Выберите папку — «Создать группы и назначить права»: скрипт найдёт группы по именам и назначит им права, не создавая дубликатов.

**Сотрудник переведён в другой отдел.** В блоке участников выберите его строки и нажмите «Удалить выбранных», затем добавьте в группы нового отдела через «Добавить пользователей...».

## Ограничения и важные замечания

- **Имена групп уникальны в пределах домена.** Две папки с одинаковым именем в разных путях получат одни и те же группы и права. Планируйте имена папок с учётом этого.
- **Переименование папки** не переименовывает группы и не меняет ACL. После переименования нужно создать новый комплект групп и прав.
- **Недопустимые символы в имени папки** для групп AD: [ ] ; = , +. Такие имена блокируются при создании групп (AD не примет их в sAMAccountName). Имя группы не должно превышать 64 символа; при длине более 20 символов выводится предупреждение.
- **Domain Local**-группы действуют на серверах в том же домене. Для доступа из другого домена используйте вложенность групп.
- Скрипт изменяет только явные ACE трёх групп FS_*; остальные разрешения папки не затрагиваются.
- Отключение наследования (галочка) меняет ACL папки: унаследованные права копируются как явные. Применяйте осознанно.
- Файловые операции выполняются под текущей учётной записью процесса; альтернативные учётные данные используются только для AD.
- Список сетевых ресурсов показывает видимые шары (скрытые ресурсы, оканчивающиеся на $, нужно вводить вручную).
- Поиск пользователей ограничен 300 результатами; для остальных используйте ручной ввод логинов.

## Частые проблемы и решения

| Симптом | Вероятная причина | Решение |
|---|---|---|
| «Модуль ActiveDirectory недоступен» | Не установлен RSAT | Установите RSAT-AD-PowerShell или Rsat.ActiveDirectory.DS-LDS.Tools |
| «The server has rejected the client credentials» | Текущий процесс не может использовать учётные данные пользователя для AD | Введите учётные данные в появившемся окне или отметьте «Другая УЗ для AD» |
| «Путь не найден или недоступен» | Нет доступа по SMB, опечатка или выбран корень сервера | Укажите путь \\сервер\шара\папка; проверьте доступ в проводнике |
| «Папка должна находиться внутри корневой папки» | Путь вне выбранного корня | Выберите папку внутри корня или измените корень |
| «Нет прав на создание групп» / access denied | Недостаточно прав в OU | Нужны права на создание групп (и OU) в выбранном подразделении |
| «Не удалось изменить права» / access denied | Нет прав на изменение ACL папки | Запустите от администратора сервера или владельца папки |
| Ошибка имени группы | В имени папки есть [ ] ; = , + или оно слишком длинное | Переименуйте папку (учтите ограничения) |
| Не работает копирование в буфер обмена | PowerShell 7 запущен без -STA | Запустите pwsh -STA или используйте Windows PowerShell 5.1 |
| В окне «кракозябры» вместо русского текста | Файл пересохранён в ANSI/Windows-1251 | Сохраните скрипт в UTF-8 с BOM |
| Окно не открывается, ошибка SetCompatibleTextRenderingDefault | Старая версия скрипта | Обновите скрипт (в 1.2 вызовы WinForms обёрнуты в try/catch) |

## Безопасность

- Используйте принцип минимальных привилегий: RO — большинству, RW — тем, кому нужно изменять файлы, FA — администраторам папки.
- Не отключайте наследование без понимания текущей модели прав: это меняет ACL папки.
- Скрипт не сохраняет пароли и не пишет их в журнал.
- Все действия фиксируются в журнале — сохраняйте его при изменениях для аудита.
- Запускайте скрипт с учётной записи администратора только на время выполнения работ.
